# Screen: Notifications

**Archetype:** 1 — Queue (read-only, no decision).
**Access (RBAC-gated):** all roles; contents are role-scoped. MFA required. Navigation (which roles reach this screen) is governed by [role-screen-matrix.md](../role-screen-matrix.md); the roles named here identify who acts on this screen.

How a staff member learns that something needs them. Built in response to flow gap G10:
without it, an officer only discovers a returned item, an SLA breach, or an escalation
by re-opening a queue. All four other RERAN modules have a notifications screen; this is
the Regulatory Authority's.

## Purpose

Surface the events a role needs to act on, each linking directly into the screen where the
action happens — so nothing waits unnoticed.

## Layout

* **Visible Sidebar:** Back-Office Sidebar (role-scoped), with an unread count badge
* **Top Bar Title:** Notifications
* **Search Bar:** Search notifications...

```
Top Bar → Filters (unread / type) → Notification list → Pagination
```

## Sections

### Section 1 — Filters

**Filter by:** unread / all · type (see §2) · date range.

### Section 2 — Notification types by role

Notifications are generated by service events, so each role receives only its own:

| Role | Receives |
| :-- | :-- |
| Compliance & Escrow Auditor | Item resubmitted after a query · SLA breach imminent/passed · claim lapsed (`M-QUE-02`) · escrow item cleared the trustee gate |
| Licensing & Registration Officer | Licensing item resubmitted · SLA breach · credential expiring · DG decision on an escalated revocation |
| Dispute Adjudication Officer | Case assigned · session due · evidence received · party responded |
| System Super Administrator | Account locked out · MFA reset requested · permission change made by another admin |
| Revenue & Finance Officer | Reconciliation run complete · discrepancy flagged · remittance due |
| Director-General / Registrar | Matter escalated for sign-off |
| Inspection & Enforcement Officer | Inspection requested · notice response due |
| State Liaison Coordinator | Harmonisation conflict detected |

### Section 3 — Notification list

| Column | Notes |
| :-- | :-- |
| Type | Category icon + label |
| Message | What happened, naming the item/subject |
| Related item | Reference; links into the screen that acts on it |
| Received | Timestamp |
| State | Unread / read |

Row click → the originating screen (queue item, case, account, reconciliation run).

### Section 4 — Empty state

States which it is: no notifications at all, or filters hiding them.

## Role Variations / Permissions

- Every role reaches this screen; the **contents are strictly role-scoped** — a role never
  sees a notification about work it cannot reach (role-screen-matrix §1).
- Read-only. Marking read/unread is the only state change; no decisions are taken here.

## Notes

- Notifications are a **convenience surface, not a system of record** — the queues and the
  [Audit Trail](audit-trail.md) remain authoritative. A missed notification must never mean
  missed work.

**In-app only — confirmed (open-questions A6).** Notifications are **not** sent by email or
SMS — not for SLA breaches, not for DG escalations. Everything surfaces inside the
back-office app. This reinforces that notifications are a convenience surface: the queues
and the [Audit Trail](audit-trail.md) remain authoritative, so nothing depends on an
officer seeing a notification.
